# agents-feedback v1.0.0

## Agent-Installable Feedback Scaffold

Version 1.0.0 ships the first stable `agents-feedback` scaffold. The release artifact expands to `.agents/feedback`, and the repository owner points an agent at `.agents/feedback/AGENTS.md` to complete installation.

## What This Provides

The scaffold gives agents a structured repository-local place to record workflow friction, missing instructions, setup problems, verification gaps, and completed improvements that should help future agent sessions in the same repository.

Feedback records are YAML files grouped by lifecycle state. Records include a short `summary`, a full `description`, sanitized `evidence`, `impact`, one or more `suggested_actions`, and an optional plan used for implementation and progress tracking.

## Highlights

- Release artifact expands directly to `.agents/feedback`.
- Bootstrap `AGENTS.md` installs the scaffold when an agent is pointed at it.
- `AGENTS.final.md` becomes the operational instruction file after installation.
- `INSTALL.md` defines the agent installation procedure.
- Managed root instruction hook template connects repository-level `AGENTS.md` files to the feedback scaffold.
- Lifecycle folders cover `new`, `planned`, `in_progress`, `in_review`, `completed`, and `archived`.
- YAML templates and JSON schemas define records and plans with agent-readable field descriptions.
- `feedback-state.mjs` summarizes feedback state with Node.js built-ins only.
- Repository checks cover scaffold contract, state behavior, installer instructions, and artifact layout.
- Public repository files define changelog, security, support, conduct, ownership, issue intake, pull request, and GitHub Actions dependency-update conventions.

## Installation

Download `agents-feedback-v1.0.0.zip` from the draft release assets after maintainer review. Extract the zip at the target repository root so `.agents/feedback/AGENTS.md` exists, then ask an agent to read that file and complete installation.

The installed scaffold has no target-repository package install, database, or background service. The optional state script requires Node.js 18 or newer when used in target repositories.

## Validation

This release is prepared with the repository release checks:

```bash
npm run release:check
npm run artifact:check
```

The release workflow builds `agents-feedback-v1.0.0.zip`, writes `agents-feedback-v1.0.0.zip.sha256`, uploads both as workflow artifacts, and attaches both files to a draft GitHub Release.

## Notes

This release is not a project changelog and does not publish feedback records. Publishing remains maintainer-controlled: pushing the approved `v1.0.0` tag creates or updates a draft release, and the maintainer publishes the draft manually.
