# agents-feedback v1.2.0

## Efficient Release Validation

Version 1.2.0 makes repository validation more efficient and keeps dependency updates compatible with the workflow contract. Each code change receives the validation it needs without running the same CI job for both a branch push and its pull request.

## What This Provides

The release keeps the dependency-free `.agents/feedback` scaffold and adds a tested GitHub Actions run policy for maintainers. Pull requests receive CI, direct pushes to `main` receive CI, and release tags use the draft release workflow's complete release gate.

## Highlights

- Runs CI for pull requests and direct pushes to `main`.
- Avoids duplicate CI on pull request branch pushes.
- Avoids an extra CI run when a release tag already runs the full release workflow.
- Cancels superseded in-progress runs for the same pull request, branch, or release tag.
- Upgrades `actions/checkout` from v6 to v7 in CI and release workflows.
- Tests workflow triggers, concurrency behavior, action majors, dependency installation, and release checks as one repository contract.
- Documents a reusable workflow policy for repositories with separate CI and tag-release jobs.

## Installation

Download `agents-feedback-v1.2.0.zip` to install this release. The similarly named `agents-feedback-v1.2.0.zip.sha256` file is optional verification metadata; do not extract it.

For a fresh installation, confirm `.agents/feedback` does not exist, extract the ZIP at the target repository root, and ask an agent to read `.agents/feedback/AGENTS.md`. For an existing installation, extract into a temporary staging directory and ask an agent to follow the staged `.agents/feedback/UPGRADE.md` procedure.

## Validation

```bash
npm ci
npm run release:check
npm run artifact:build
```

The workflow contract verifies that CI and release jobs use current action majors, install repository dependencies, run the complete release gate, and do not schedule redundant validation events.

## Notes

The package release is v1.2.0. The installed record and plan contracts remain `feedback-record.v1` and `feedback-plan.v1`, and the installed scaffold remains dependency-free.

The reusable workflow pattern is to validate pull requests, validate direct pushes only on the protected integration branch, reserve tag pushes for release work, and cancel superseded runs by pull request, branch, or tag key.

Tagging, pushing, drafting on GitHub, and publication remain maintainer-approved actions.
